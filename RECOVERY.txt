ActionForge deployment recovery

Recovered from https://actionforge.app/ at the owner's request.
The deployed application modules, styles, fonts, animations and models are
preserved under public/. THIRD-PARTY-NOTICES.txt retains the original notices.
public/recovery-inventory.json records each recovered file's original SHA-256.

This restores the published JavaScript build, not the lost authoring source.
The TypeScript code provides the Vite build, GitHub Pages compatibility,
portable scene sharing, recovery tooling and browser checks.

Requirements: Node.js 24 and npm.
  npm ci
  npm run dev
  npm run lint
  npm run build
  npm test

Browser checks use Google Chrome at /usr/bin/google-chrome by default.
Set CHROME_PATH to use another installed Chromium executable.
Set BASE_PATH when building for a location other than /actionforge/.

The GitHub Actions workflow publishes dist/ to GitHub Pages on pushes to main.
To recover a newer published build, run npm run recover. This fetches public
resources recursively and inspects rendered pages with Playwright.
Review changes before publishing: changed share-function signatures deliberately
fail the build rather than silently breaking the static hosting adaptation.

GitHub Pages cannot host the original server's /api/share storage.
New share links therefore encode the scene into a portable URL fragment;
the original scene reader restores it without a server or external service.
Original server databases, existing short-link records, private files and
unpublished source cannot be recovered from the public deployment.
The original third-party social and support links remain external.

The published site returns 404 for its optional animals/list.json catalog.
An empty local catalog preserves its existing no-animals behavior without a
failed network request on GitHub Pages.
